# MailMaster · 邮件定时推广助手

面向 **Windows 10** 的桌面端批量推广邮件工具（Electron 实现）。用于配置推广名单与邮件内容模板、按规则自动替换变量、按拟人节奏定时或手动批量投递、多账号轮询发信，并通过 IMAP 自动监听退信把无效地址从名单中剔除，同时跟踪每一封邮件的投递状态。

---

| **推广邮件列表** | 维护 公司名 / 联系人 / 邮件称呼 / 邮件地址 / 电话 / 职位 / 城市 / 标签 等基础信息；每个地址单独统计 **成功数、失败数、退信数**；支持 CSV 导入导出、标签分组、批量删除、手动标记退信与**一键解除退信标记** |

| **发信邮箱配置** | 管理用于群发的发信账号，支持 **普通邮箱 SMTP** 与 **腾讯云邮件推送（SES）** 两类渠道；可添加多个账号并为不同推广任务指定不同发信地址；SMTP 侧置顶「封号风险」提示与 7 家常用服务商快捷预设（含 IMAP 服务器联动填充）；每个账号可单独开启 **IMAP 退信监听**；腾讯云侧可**查询剩余免费额度**（官方 1000 封免费额度） |

### 定时规则

支持 6 种执行方式，可在任务中自由组合：

| 类型 | 说明 |
| --- | --- |
| 仅手动 | 不自动触发，创建后随时点击「立即推广」，用于临时推广 |
| 每 N 分钟 | 固定间隔自动执行（如每 30 分钟） |
| 每天 | 每天固定时间（如 09:30） |
| 每周 | 可选多个星期几 + 时间（如 每周一、三、五 09:30） |
| **每月** | 可选多个日期 + 时间（如 每月 1 日、15 日 09:30），短月份自动落到当月最后一天 |
| 指定时间一次 | 在指定时刻执行一次后自动完成 |

## 二、模板变量

在模板主题与正文中使用 `{{变量}}`，发送时会**按该封邮件对应的收件人自动替换**。变量名支持中文标签、英文键名与常见别名（不区分大小写）。

| 变量 | 别名示例 | 取值来源 |
| --- | --- | --- |
| `{{公司名}}` | {{公司}}、{{单位}}、{{company}} | 邮件列表 · 公司名 |
| `{{联系人}}` | {{姓名}}、{{名字}}、{{contact}} | 邮件列表 · 联系人 |
| `{{称呼}}` | {{尊称}}、{{称谓}}、{{salutation}} | 邮件列表 · 邮件称呼 |
| `{{邮件地址}}` | {{邮箱}}、{{email}} | 邮件列表 · 邮件地址 |
| `{{电话}}` | {{手机}}、{{手机号}}、{{phone}} | 邮件列表 · 电话 |
| `{{职位}}` `{{城市}}` `{{标签}}` `{{备注}}` | — | 邮件列表对应字段 |
| `{{日期}}` `{{时间}}` `{{年份}}` `{{月份}}` `{{日期时间}}` | — | 发送时刻自动生成 |
| `{{发件人}}` `{{发件方公司}}` | — | 系统设置中的发件人与发件方公司名 |
| `{{序号}}` `{{总数}}` | — | 本批次第几封 / 共几封 |

写法示例：

```
尊敬的{{称呼}}{{联系人}}：

您好！我是{{发件方公司}}的{{发件人}}。了解到{{公司名}}在{{城市}}的业务发展，
我们近期落地的方案或许对您有帮助……如方便可联系您电话{{电话}}。
```

## 三、Spintax 同义词轮换（让每封邮件都不同）

只用变量替换时，同一批邮件除了称谓以外**字面完全一致**，容易被收件端按内容指纹判定为群发。Spintax 用大括号同义词组让每封邮件的**主题与正文都不同**。

### 语法

| 写法 | 效果 |
| --- | --- |
| `{您好\|你好\|幸会}` | 每次渲染随机取其中一个 |
| `{您好\|{早上好\|下午好}}` | 支持嵌套 |
| `\{` `\}` | 输出字面大括号 |
| 不含 `\|` 的大括号，如 `{}` | 原样输出，**不会被解析** |

> 只有「**含顶层 `\|` 的大括号组**」才会被当成 Spintax，因此与既有的 `{{变量}}` 语法完全不冲突，正文里正常写 `{}` 也不会被误解析。Spintax 展开前先把 `{{变量}}` 抽成占位符保护起来，变量内部即使含大括号也不会被破坏。

### 主题 × 正文 = 组合空间

「可产生的不同内容数」= **主题变体数 × 正文变体数**。例如主题有 4 种说法、正文有 6 种说法，就是 24 种组合。模板页会实时显示：

- 本模板可产生 **N** 种不同内容（主题 A 种 × 正文 B 种），当前推广列表约 M 个地址；
- 若 **N ≥ M**，标注「可覆盖整批收件人」；否则提示「少于收件人数，超出部分会重复」；
- 给出「随机抽样（每次刷新都不同）」列表，以及「**换一组措辞**」按钮逐版对照；
- 预览标签显示「第 X / N 种措辞」，与引擎内部的组合编号一致。

### 「整批不重复」是怎么保证的

引擎不靠「随机撞运气」，而是把主题×正文的组合**统一编号为 0 … N-1 的组合空间**，同一批次内用一个 `Set` 记录已用过的编号，发送时优先挑选**尚未使用过**的编号：

- 只要 **N ≥ 本批收件人数**，这一批每封邮件的主题+正文组合必然唯一；
- 组合用尽后自动开启新一轮（重新计数），不会因为「找不到没用过的」而卡住或报错。

推荐做法：在问候语、主题、行动号召三处各放一组同义词，通常就能覆盖几千人规模的批次。

## 四、发送节奏与多账号轮询

两个能力解决同一个问题：**别让服务商看出来这是机器在定时群发。**

### 4.1 随机延迟与长停顿

| 参数 | 说明 |
| --- | --- |
| 间隔模式 | **固定间隔**（精确可预期）/ **随机延迟**（拟人，推荐） |
| 每封间隔（秒） | 固定模式使用 |
| 随机最小 / 最大延迟（秒） | 随机模式使用，每两封之间在该区间内取值 |
| 每多少封后长停顿 | 如「每 10 封」停下休息一次，0 表示不启用 |
| 长停顿最短 / 最长（秒） | 长停顿的时长区间 |
| 每小时发送上限 | 达到后**自动等待到下一个小时窗口**再继续（0 = 不限） |
| 每日发送上限 | 与「发信账号自身的每日上限」双重控制 |
| 失败重试次数 | 临时性失败（4xx / 超时 / 限流）自动重试 |

配置上限保护：单个延迟最多 6 小时、`burstEvery` 最多 5000、`maxRetries` 最多 20，避免误填出「等 3 天」这类离谱配置。

### 4.2 节奏预设

推广任务页与系统设置页都提供四个预设，一键套用后仍可手工微调：

| 预设 | 参数 | 适用场景 |
| --- | --- | --- |
| **稳健匀速** | 固定 10 秒/封，日限 200 | 自建 SMTP 通道 |
| **拟人节奏（推荐）** | 20–90 秒随机 + 每 10 封长休息 3–7 分钟 + 每小时 60 封上限 | 最接近人工发送 |
| **保守低频** | 1–3 分钟随机 + 每 8 封长休息 10–20 分钟 + 每小时 20 封上限 | 普通邮箱 SMTP（个人邮箱群发上限通常仅数十至数百封/天） |
| **快速通道** | 固定 5 秒/封，日限 1000，重试 2 次 | 腾讯云邮件推送等专业通道 |

### 4.3 整批耗时估算

任务的「收件人范围」里点「统计命中人数」后，节奏面板会按**当前节奏 + 命中人数**实时给出整批预计耗时（例如「共 1,240 位收件人 · 按当前节奏预计整批耗时 1 小时 12 分」），并同时显示主进程生成的节奏说明文字。估算超过 12 小时会转为警示色，便于在保存前发现「这批要发到明天」。

> 界面上所有节奏说明都由主进程的 `pacing` 模块生成（`describe()` / `humanizeMs()` / `estimateMs()`），与真正执行时的计算同源，不会出现「界面说的」和「实际做的」不一致。

### 4.4 多账号轮询发送

一个推广任务可以从**多个发信邮箱**轮流发出，避免所有邮件都来自同一个地址。

| 项目 | 说明 |
| --- | --- |
| 账号模式 | **单个账号** / **多账号轮询发送**（至少勾选 2 个，已停用的账号不参与） |
| 轮询策略 · 轮询（推荐） | 按顺序依次使用每个账号，用量最均衡 |
| 轮询策略 · 随机 | 每封在可用账号中随机挑选，分布更不规律 |

- 达到**日发送上限**的账号会被自动跳过，其余账号继续投递；
- 投递记录里会写明该封邮件用的是**哪个发信邮箱**，便于追溯是哪个账号出了问题；
- 任务卡片上会直接标出「账号池：a@x.com 等 3 个 · 策略 轮询」与节奏摘要。

## 五、IMAP 退信监听与退信剔除

SMTP 当场拒收只是退信的一部分；**收件人不存在、邮箱已满、被对方服务器拒收**等情况往往在投递成功之后，以**投递失败报告（DSN）邮件**的形式回到发信邮箱里。这一节讲的机制会自动把它们捞出来。

### 5.1 工作方式

1. **账号级开启**：在「发信邮箱配置 → 编辑账号 → 退信监听（IMAP）」打开开关，填写 IMAP 服务器、端口、加密方式、登录名（不填则用邮箱地址）、密码 / 授权码、收件箱（默认 `INBOX`）与回溯天数（默认 30 天）；点「测试 IMAP 收信」可当场验证能否连上。
2. **定时轮询**：按全局轮询间隔（默认 5 分钟）自动登录各账号收件箱，搜索近 N 天内未读的疑似退信邮件，逐封拉取原文。
3. **解析 DSN**：递归解析 MIME 结构，解码 RFC 2047 编码的主题、base64 与 quoted-printable 正文，从 `message/delivery-status` 中提取 `Final-Recipient`、`Action`、`Status`、`Diagnostic-Code` 与 `Original-Message-ID`。
4. **归类与打标**：按状态码归类为**硬退信**（`5.x.x`，如 `550 5.1.1 user unknown`）/ **临时退信**（`4.x.x`）/ **被拒收**；命中后给对应联系人打上退信标记。
5. **从发送列表剔除**：被标记的地址**不会出现在任何推广任务的发送列表中**——受众解析、命中人数统计、「仅可发送」列表、模板页的可覆盖人数都会自动排除它们。
6. **可手动解除**：标记**不是永久的**。在「退信监听 → 已标记退信的地址」或「推广邮件列表」的行内点「解除退信」，确认后该地址重新进入下一轮推广的发送列表（支持批量解除）。

### 5.2 监听总开关

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 开启自动轮询 | 开 | 关闭后只在你点击「立即检查退信」时扫描 |
| 轮询间隔（分钟） | 5 | 建议 5～30 分钟；过于频繁会持续登录邮箱 |
| 自动标记退信地址 | 开 | 关闭后仅登记退信事件，不自动剔除地址 |
| 自动标记的退信类型 | 仅硬退信 / 被拒收 | 也可选「所有退信（含临时退信）」；临时退信多为短时限流，建议人工处理 |

### 5.3 退信监听页能看到什么

- **四张统计卡**：监听状态（运行中 / 仅手动 / 未启用，含账号数与轮询间隔）、已标记退信地址数、退信事件总数、上次检查时间与相对时间；
- **各账号监听状态**：IMAP 服务器、收件箱、监听开关、上次检查、上次命中数、配置完整性说明（缺什么会直接说明原因），以及「检查该账号 / 测试连接 / 去配置」三个动作；
- **已标记退信的地址**：公司名 / 联系人、地址、退信类型、状态码、来源（IMAP 自动监听 / 人工标记）、标记时间、原因与诊断信息，以及「解除标记」；
- **退信事件明细**：时间、发信账号、收件人、归类、状态码、诊断信息、关联任务与**匹配情况**；点「详情」可看到 14 项完整字段（含原邮件主题、`Original-Message-ID`、报告发件人、邮箱 UID、多收件人列表）；
- **筛选**：按发信账号、退信类型（硬 / 临时 / 被拒收）、匹配情况（已匹配 / 未匹配）、关键字（地址 / 公司 / 状态码）。

### 5.4 幂等与安全

- 退信事件按「发信账号 + 邮箱 UID」去重，同一封 DSN 被反复扫到**只登记一次、只标记一次**；
- 已读标记（`\Seen`）默认打开，扫描过的 DSN 不会在下轮重复处理；
- 报告里的地址若不在当前邮件列表中，只登记为「未匹配」，**不会误标记任何联系人**；
- IMAP 连接只读取收件箱、标记已读与登出，不做任何删除或移动。

## 六、运行环境与使用

### 开发 / 运行

```bash
npm install          # 安装依赖（含 Electron 运行时）
npm start            # 启动应用
npm run dev          # 启动并打开开发者工具
npm test             # 逻辑与数据契约自测（103 项，无需 SMTP / IMAP）
npm run preview      # 浏览器 UI 预览（内存模拟数据，不落盘、不发信）
npm run smoke        # 无头 UI 冒烟测试：真实渲染九个页面并模拟关键交互（需先起 preview）
```

> `npm run smoke` 用 Electron 隐藏窗口加载预览站点，逐页断言渲染结果并模拟点击（节奏预设、账号池切换、换一组措辞、退信解除、监听设置保存等），最后汇总未捕获异常与 `console.error`。若环境里存在 `ELECTRON_RUN_AS_NODE=1`，需先清除该变量（脚本会给出手把手指令）。

### 打包 Windows 安装包

```bash
npm run build:win            # 生成 NSIS 安装包 + 免安装便携版（dist/ 目录）
npm run build:win-portable   # 仅生成免安装便携版
```

- 产物：`dist/MailMaster-1.0.2-x64-setup.exe`（安装版，可选安装目录、创建桌面与开始菜单快捷方式）与 `dist/MailMaster-1.0.2-portable.exe`（免安装便携版）。
- 版本号取自 `package.json` 的 `version` 字段，改版本后重新打包即按新版本命名产物。
- 应用图标由 `tools/make-icon.py` 生成（`build/icon.ico`，纯 Python 无依赖，可重新执行覆盖）。

**在 macOS 上交叉打包 Windows 目标（已实测通过）**

在 Intel Mac 上执行 `npm run build:win` 可以直接产出 Windows 安装包，无需 Windows 机器。electron-builder 会自动下载所需的全部工具链并缓存到 `~/Library/Caches/electron-builder/`：

| 资源 | 用途 | 大小 |
| --- | --- | --- |
| `electron-v31.7.7-win32-x64.zip` | Windows 版 Electron 运行时 | 111 MB |
| `winCodeSign-2.6.0.7z` | 给 exe 打签名 / 嵌入图标与版本信息 | 5.6 MB |
| `wine-4.0.1-mac.7z` | macOS 上运行 Windows 版 `rcedit` / `makensis` | 19 MB |
| `nsis-3.0.4.1.7z` + `nsis-resources-3.4.1.7z` | 生成 NSIS 安装器 | 2 MB |

首次打包约需 5–8 分钟（主要是下载），之后走缓存约 1–3 分钟。

> **实测结果**：产物为标准 NSIS 自解压安装包（PE32 可执行），内嵌 136 个文件 / 31 个目录，解压后约 271 MB，其中 `MailMaster.exe` 为 **x64**，`resources/app` 完整包含应用源码与 `nodemailer` 运行时依赖。安装器自身的 stub 是 32 位，这是 NSIS 的固有行为，安装出来的应用是 64 位。

> **关于 asar**：默认配置会把应用源码打成 `app.asar` 单文件。若打包环境禁止写入 asar（表现为 `Brokered file token refused` 之类的写入拦截），可临时关闭：
> ```bash
> node node_modules/electron-builder/out/cli/cli.js --win --x64 --config.asar=false
> ```
> 关闭后 `resources/app` 以普通目录形式存在，应用功能完全一致，仅启动时少一次归档读取、源码不再被合并保护。**在 Windows 上正常打包时请保持默认（开启 asar）。**

### 首次使用流程

1. **发信邮箱配置**：新增一个发信账号，选择渠道并点击「测试连接」。
   - **普通邮箱 SMTP**：可点常用服务商预设一键填入服务器与端口（同时联动填入 IMAP 收信服务器）。常用：腾讯企业邮 `smtp.exmail.qq.com:465`（SSL）、网易企业邮 `smtp.qiye.163.com:465`、QQ 邮箱 `smtp.qq.com:465`（用授权码）、Gmail `smtp.gmail.com:465`（应用专用密码）。
     > ⚠ 页面顶部与表单内均有**封号风险提示**：使用普通邮箱群发，服务商可能限速、限制发信甚至封禁账号（个人邮箱每日群发上限通常仅数十至数百封）。建议优先改用腾讯云邮件推送等专业通道，并控制发送频率与名单质量。
   - **腾讯云邮件推送（SES）**：填写腾讯云 `SecretId` / `SecretKey`、地域与**已审核通过的发信模板 ID**（或在控制台申请 HTML 直发权限后改用直发模式）；保存后可在账号卡片点「查询额度」查看**剩余免费额度**。
   - **开启退信监听（可选但推荐）**：同一弹窗的「退信监听（IMAP）」面板打开开关，填好 IMAP 服务器与授权码后点「测试 IMAP 收信」验证。
2. **推广邮件列表**：新增联系人，或用「导入 CSV」批量导入（表头支持中文与常见别名，重复邮箱默认跳过）。
3. **内容模板**：编辑主题与正文，用变量按钮插入 `{{公司名}}`、`{{称呼}}` 等；再用 `{说法一|说法二}` 给问候语与主题各加一组同义词，右侧会提示本模板可产生多少种不同内容。点「预览效果」可弹窗放大查看，或点「独立窗口预览」在新窗口里按完整尺寸查看邮件样式（详见下节）。
4. **推广任务**：切换「临时推广任务 / 定时推广任务」，选择模板、**发信账号（可用多账号轮询）**与受众范围，按需套用**发送节奏预设**或手工调整随机延迟，设置执行方式后保存。
5. **执行**：临时任务点「立即推广」；定时任务到点自动执行，也可在「定时任务管理」页点「立即执行」。
6. **投递状态**：查看每封邮件的投递结果、发信邮箱与失败原因，对失败项单独或批量重发；「总览看板」查看整体统计与下一次推广倒计时。
7. **退信监听**：在「退信监听」页确认监听运行中，必要时点「立即检查退信」；被剔除的地址可在该页或「推广邮件列表」页手动解除。

> **默认处于「试运行模式」**：整条流程（受众解析 → 模板替换 → 逐封发送 → 结果记录与统计）都会完整走一遍，但不会真正发出邮件。确认无误后，在「系统设置 → 发送模式」切换为「真实发送」，或在单个任务中关闭试运行。
>
> 需要注意的是，**试运行不会真的投递，因此也不会产生 DSN 退信**；退信监听是要连真实收件箱的，其效果需要搭配真实发送才能观察到。

### 独立窗口预览（按完整尺寸查看邮件样式）

主界面的预览区只有半栏宽，核对排版不够直观。以下三个入口都可把**当前邮件内容**送到一个独立窗口，按真实邮箱阅读区宽度完整展示：

| 入口 | 位置 | 内容 |
| --- | --- | --- |
| 内容模板 → 右侧「当前模板预览」 | 面板标题右侧「独立窗口预览」 | 左侧编辑区当前内容（实时渲染结果） |
| 内容模板 → 「预览效果」弹窗 | 弹窗右下角「独立窗口预览」 | 同上 |
| 投递状态 → 「查看」弹窗 | 弹窗右下角「独立窗口预览」 | 该封邮件**实际投递时**的内容（含真实投递时间与发信邮箱） |

独立窗口的特性：

- **完整尺寸**：正文按选定宽度居中显示，默认 **720px**，可切 `窄 600 / 标准 720 / 宽 900 / 自适应`；字号可选 小 / 中 / 大。宽度与字号会被记住，下次打开沿用。
- **邮件阅读视图**：顶部还原 发件人（含发信邮箱）、收件人（联系人 · 称呼 · 邮箱）、公司、时间；正文白底深字渲染；变量缺失时给出黄色提示。
- **打印 / 另存 PDF**：右上角「打印 / PDF」；打印时自动隐藏工具条与卡片阴影，只输出邮件本体。
- **可刷新**：内容同时缓存在本地，窗口刷新或主窗口关闭后仍能显示最近一次预览。
- **实现**：`src/renderer/preview.html` + `preview.css` + `js/preview-window.js`，与主界面完全解耦，靠 `postMessage` 握手接收内容；主进程 `setWindowOpenHandler` 只放行这一个本地页面（其余 `http(s)` 外链仍交给系统浏览器打开）。

## 七、发信渠道对比

| | 普通邮箱 SMTP | 腾讯云邮件推送（SES） |
| --- | --- | --- |
| 账号凭证 | 邮箱地址 + 密码 / 授权码 | 腾讯云 SecretId / SecretKey |
| 发信地址 | 该邮箱地址本身 | 控制台已验证的发信地址 |
| 内容形式 | 主题 + HTML / 文本直接发送 | 模板发送（传模板 ID + 变量），或申请 HTML 直发权限 |
| 免费额度 | 无官方额度概念，按服务商规则受限 | 每账号 **1000 封免费额度**（官方标注不限有效期），用完后按量计费 |
| 额度查询 | 不适用 | 账号卡片「查询额度」调腾讯云接口读取套餐包剩余量 |
| 退信监听 | **可用**（收件箱里能收到 DSN 退信报告，按 IMAP 自动扫描） | 不适用（无收件箱，退信由腾讯云侧处理） |
| 主要风险 | **群发易被限速 / 封号**，送达率受邮箱信誉影响 | 需先完成域名与地址验证、模板审核 |

> 「查询额度」会先调用腾讯云套餐包 / 账户接口；若接口字段无法识别，会**原样展示返回内容**并同时给出本应用的本地用量估算，而不是编造数字。本地估算口径为「免费额度总量 − 本应用累计真实发送量」，仅统计真实发送（试运行不计入）。

## 八、投递结果与退信处理

### 投递结果归类

- **成功**：SMTP 服务器接受投递，或腾讯云接口返回 `RequestId`（`MessageId` 无错误）。
- **失败**：分两类，临时性错误（4xx、超时、限流）会按任务配置的重试次数自动重试；永久性错误直接记失败并保留原因。
- **退信**：分两个来源，二者共同决定「这个地址还会不会继续收到推广邮件」——
  1. **SMTP 即时退信**：投递当场被拒收（`5.1.1`、`user unknown`、`mailbox not found` 等），该地址被**自动停用**；
  2. **IMAP 事后回执退信**：投递成功后由对端服务器异步退回的 DSN 报告，由「退信监听」扫描识别并**打上退信标记**（见第五节）。

### 熔断与配额

- **熔断保护**：单次执行中退信数超过阈值（默认 5）且退信率高于 30% 时自动暂停任务，并提示检查名单质量。
- **每日配额**：按任务配置的每日上限与**发信账号自身的每日上限**双重控制真实发送量，任一达到上限即自动暂停，剩余收件人可在次日继续；腾讯云账号免费额度耗尽时也会提示。
- **每小时配额**：达到每小时上限后自动等待到下一个小时窗口，不会硬发也不会失败。

### 剔除与恢复

- 被剔除的地址（SMTP 即时退信停用、IMAP 退信标记）都不会出现在受众解析结果里，「仅可发送」列表、命中人数、模板可覆盖人数统计也都会排除它们；
- 这些地址**不会收到推广邮件，直到被手动恢复**：在「退信监听」页或「推广邮件列表」页点「解除退信」即可；SMTP 即时退信导致的停用可在联系人编辑弹窗里重新启用订阅。

## 十、设计要点

- **数据存储**：全部数据保存在单个 JSON 文件（`%APPDATA%/MailMaster/mailmaster-data.json`，可在「系统设置 → 打开数据目录」定位），采用「写临时文件 + rename」的原子写入与写入节流，避免高频发送时磁盘抖动，也避免使用原生模块（Windows 上无需编译环境）。
- **进程隔离**：渲染层只通过 `contextBridge` 白名单接口访问主进程能力，`nodeIntegration` 关闭；渲染层带 CSP 限制。
- **开窗策略收紧**：`setWindowOpenHandler` 默认拒绝一切新窗口，仅放行本地 `preview.html`（独立邮件预览，固定 1040×940、带系统边框）；`http(s)` 链接一律交给系统浏览器打开，避免应用内出现不受控的浏览窗口。
- **独立预览的握手方式**：不用「打开后定时盲发内容」，而是窗口加载完成后主动 `postMessage` 报 ready 并带上随机 `nonce`，主界面收到匹配的 nonce 才投递内容，时序确定且不会串窗口；同时把内容写入 `localStorage` 作为兜底，窗口刷新或主窗口已关闭时仍能显示最近一次预览。
- **Spintax 与变量不打架**：只有「含顶层 `|` 的大括号组」被当作 Spintax；展开前先把 `{{变量}}` 抽成私有区字符占位符（`\u0001序号\u0002`）保护起来，展开后再还原，因此变量内部即使出现大括号也不会被误解析。
- **组合空间而非随机撞运气**：主题变体数 × 正文变体数构成统一编号的组合空间，批次内用 `Set` 记录已用编号优选取未用者，从而**只要组合数 ≥ 收件人数就保证本批不重复**；用尽后自动开启新一轮，不会卡死。
- **节奏计算纯函数化**：`pacing.js` 不依赖时间与网络，随机源可注入（`rng`），因此「同一配置 + 同一随机种子」结果可复现，测试可断言，也便于界面的耗时估算与实际执行共用同一套计算。
- **账号池无状态依赖**：`AccountPool` 只管「下一个该用谁」，账号是否可用（停用 / 达到日限）由调用方通过 `isUsable` 回调判断，模块本身不碰数据库，便于单测。
- **IMAP 客户端零依赖**：只用 Node 内置 `tls` / `net` 实现，命令严格串行化并处理 `+` 续行握手，不引入第三方 IMAP 库，保持打包体积小、无原生模块。
- **退信标记可逆**：`contacts.bounceMarked` + `bounceInfo` 只影响受众解析，解除标记即恢复投递资格；事件与标记都记录来源（`imap` / `manual`），便于区分自动识别与人工判断。
- **退信事件幂等**：按「发信账号 + 邮箱 UID」去重，同一封 DSN 被反复扫到只登记一次、只标记一次；报告里不在名单中的地址只登记为「未匹配」，不会误标任何联系人。
- **发信渠道抽象**：`mailer.createSender(account)` 统一返回 `{ provider, send(mail), close() }`，执行引擎只依赖该接口，因此 SMTP 与腾讯云 SES 两条通道可互换，任务只需绑定不同的发信账号。
- **腾讯云签名自实现**：`tencent-ses.js` 用 Node 内置 `crypto` 手写 TC3-HMAC-SHA256 签名链（`secretDate → secretService → secretSigning → signature`），不引入腾讯云 SDK，保持依赖精简、打包体积小。
- **额度数据诚实性**：腾讯云接口字段名可能随版本变化，解析采用「宽容匹配」，识别不出时返回 `null` 并原样展示接口返回，绝不用推测值冒充官方额度。
- **界面文案与执行逻辑同源**：节奏说明、耗时估算、退信监听的就绪状态判断都由主进程模块生成后下发，界面不自行拼文案，避免「界面说的」与「引擎做的」分叉。
- **浏览器预览层可测**：`dev-mock.js` 在无 Electron 时提供同一套 `window.api` 的内存实现（含 Spintax、节奏、退信监听的等价算法），因此界面可以在浏览器里完整点通，测试也会断言「模拟层与主进程算法输出一致」。
- **旧配置自动迁移**：从早期「系统设置里的单一 SMTP」升级时，首次启动会自动把旧配置迁移成 `accounts` 数组中的第一个发信账号，无需手工重填；旧任务缺少 `mode` 字段时按固定间隔语义处理，行为不变。
- **调度唯一性**：应用单实例运行（重复启动会激活已有窗口），避免多进程重复触发定时推广；关闭窗口后驻留系统托盘继续执行定时任务。
- **试运行模拟**：试运行结果由邮箱哈希决定，同一邮箱结果稳定，便于反复演示与验证界面流程。退信监听连的是真实收件箱，与试运行互不影响。
- **上线前双重校验**：`npm test`（数据契约与模块逻辑）+ `npm run smoke`（Electron 真实渲染与交互、零未捕获异常）两道关卡都通过才打包。
- **合规提醒**：请遵守《反垃圾邮件》相关法规与邮箱服务商政策，控制发送频率、保留退订说明；退信地址请及时清理。普通邮箱 SMTP 群发存在**限速与封号风险**，正式推广建议使用腾讯云邮件推送等专业通道。

## 十一、版本记录

### 1.0.2

- 新增 **Spintax 同义词轮换**：模板中用 `{说法一|说法二}` 写同义词（支持嵌套、`\{` 转义，与 `{{变量}}` 语法互不干扰），使每封邮件的**主题与正文都不同**；模板页实时给出「主题 A 种 × 正文 B 种 = N 种不同内容」统计、是否足以覆盖整批收件人的判断、随机抽样列表与「换一组措辞」逐版对照，预览标签显示「第 X / N 种措辞」。引擎把主题×正文统一编号为组合空间，批次内优选取未用过的编号，**只要组合数 ≥ 收件人数就保证本批不重复**。
- 新增 **发送节奏与随机延迟**：由「固定间隔」升级为完整节奏模型——固定间隔 / 随机延迟（区间内浮动）/ 每 N 封长停顿 / 每小时上限（超出自动等待到下一个小时窗口）/ 每日上限 / 失败重试；提供「稳健匀速 / 拟人节奏（推荐）/ 保守低频 / 快速通道」四个预设一键套用；任务页按命中人数**实时估算整批耗时**，超过 12 小时给出警示。
- 新增 **多账号轮询发送**：一个推广任务可在多个发信邮箱之间**轮询或随机**投递，避免所有邮件来自同一地址；达到日上限的账号自动跳过，投递记录与任务卡片都标明该封邮件用的是哪个发信邮箱。
- 新增 **IMAP 自动监听退信**：账号级开启后按全局间隔（默认 5 分钟）扫描发信邮箱收件箱，零依赖 IMAP 客户端 + MIME/DSN 解析提取收件人、状态码与诊断信息，归类硬退信 / 临时退信 / 被拒收；命中后**自动标记并从所有推广的发送列表中剔除**（受众解析、命中人数、「仅可发送」列表同步排除）。标记**可手动解除**，解除后地址重新进入发送列表；新增「退信监听」页展示账号监听状态、已标记地址、退信事件明细与 14 项详情，支持按账号 / 类型 / 匹配情况 / 关键字筛选，以及批量解除。
- 退信事件按「发信账号 + 邮箱 UID」**幂等去重**；报告中的地址若不在名单内只登记为「未匹配」，不会误标联系人；账号弹窗的「测试 IMAP 收信」支持对**未保存的新账号**直接验证。
- 配套改造：总览看板新增「退信剔除地址」统计卡与页头剔除提示；推广邮件列表新增退信标记列、行内退信 / 解除按钮与「批量解除退信标记」，状态筛选新增「已标记退信（被剔除）」；发信邮箱配置新增「退信监听（IMAP）」面板、IMAP 测试按钮与账号卡片监听徽标，服务商预设联动填入 IMAP 服务器；系统设置新增「默认发送节奏」与「IMAP 退信监听」两个面板；投递状态页页头区分 SMTP 即时退信与 IMAP 事后回执退信。
- 校验与工程：新增 `npm run smoke` 无头 UI 冒烟测试（Electron 真实渲染九个页面并模拟关键交互，断言 75 项、零未捕获异常）；`npm test` 扩充到 **103 项**，覆盖 Spintax、发送节奏、账号池、MIME/DSN 解析、IMAP 监听（本地模拟服务器）与浏览器预览模拟层的算法一致性。

### 1.0.1
