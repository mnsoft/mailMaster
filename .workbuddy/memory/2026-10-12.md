### 环境隔离造成的坑与解法（重要，下次直接照做）
1. **网络通但文件写操作被拦**：`npm install` 报 `CODEBUDDY_BROKER_DENY`，卡在写 `node_modules/.bin/*` 的 rename（源文件不存在 → ENOENT 被包装成拒绝）。`--no-bin-links` 只跳过顶层，嵌套的 `node_modules/*/node_modules/.bin` 仍失败。**解法**：让 npm 跑完（包其实已解压），再手工建链接：
   `ln -s ../electron/cli.js node_modules/.bin/electron`、`ln -s ../electron-builder/cli.js node_modules/.bin/electron-builder`。
2. **`tar --strip-components=1` 会丢文件**：用它解压到 `node_modules` 时，包内子目录（`lib/`、`dist/`）被丢弃 → require 报 MODULE_NOT_FOUND。**解法**：先解压到同设备暂存目录（**不带** strip），再 `mv package <目标>`。
3. **`fs.renameSync` 不能跨设备**（/tmp → /Volumes）：报 EXDEV + BROKER_DENY。同设备 `mv` 正常。
4. **asar 打包被拦**：electron-builder 的 `AsarPackager` 用 `createWriteStream` 写 `app.asar` 被拒（`Brokered file token refused: modify backup failed`）；`@electron/asar` CLI 同样失败；换输出目录到本地盘也无效。**解法**：`--config.asar=false`。功能等价，仅源码不合并；**在 Windows 上打包请保持默认开启 asar**。
5. 用 `require.resolve` 全库验证包可加载，比"查 main 文件是否存在"准确得多（能正确处理无扩展名 main、`exports` 字段）。`@types/*`、`type-fest`、`undici-types` 无运行时入口属正常，`dunder-proto`/`math-intrinsics` 用 `exports` 限制子路径导出也属正常。

### Electron 启动必知
- 本环境默认有 `ELECTRON_RUN_AS_NODE=1`，会让 Electron 退化为纯 Node，`require('electron')` 返回路径字符串而非 API，报 `Cannot read properties of undefined (reading 'requestSingleInstanceLock')`。**启动前必须 `env -u ELECTRON_RUN_AS_NODE`**。
- 强杀主进程会残留 `~/Library/Application Support/MailMaster/SingletonLock`，导致后续启动**静默立即退出**（看起来像启动失败）。排查启动问题时先清 `Singleton*`。
